Every Fantasy Premier League tool will tell you that a fixture is green or red. Almost none will tell you why, and none of them account for the thing that decides most gameweeks: that difficulty is not a property of a team, it is a property of a pairing. Gaffer IQ exists to model the pairing.

What it does

The engine scores a fixture by combining four signals rather than one: current team form, the home and away split for both sides, a style clash rating derived from how each team actually creates and concedes chances, and a position-level counter-matchup — how this defence tends to handle this kind of attacker.((Style profiling uses Understat expected-goals data rather than the FPL API's own numbers, which carry no shot-quality information at all.))

That score then drives four modules that all read from the same engine:

  • Matchup Analyser — one fixture, taken apart into its contributing signals, so the rating can be argued with rather than just trusted.
  • Player Ranker — every player sorted by projected return over a chosen horizon, with full names rather than the FPL API's web names.
  • GW Decision Dashboard — captain, bench order and the marginal calls for the coming gameweek.
  • Transfer Planner — multi-week planning against the fixture ticker, including hit maths.

How it is built

The proxy

The FPL API sends no CORS headers, so a browser cannot call it directly. A small Vercel serverless function sits in front of it and forwards the responses. That one function is the only server-side code in the project; everything else is static.

The engine

Scoring is a pure function: fixtures and form data in, a rating out, no reads from anything the caller cannot see. That constraint was not architectural purity for its own sake — it is what makes the ratings testable against real results at the end of a gameweek, which is the only way a model like this ever gets calibrated.

A rating you cannot check against last Saturday is a horoscope with extra steps.
